# libutp 限制与边界

更新时间：2026-09-19

本文记录当前 C11 实现中会影响调用方、线上协议或资源使用的限制。代码中的所有数字并不都是同一种限制，阅读时请区分：

| 标记 | 含义 |
|---|---|
| 协议硬限制 | 线格式、地址族或协议状态机要求，不能通过调参突破。 |
| API 限制 | 公共 API 接受的输入范围；违反时返回参数错误。 |
| 默认值 | 由 `*_INIT` 初始化宏提供。 |
| 资源保护 | 防止单个连接或异常报文无限占用内存/队列；耗尽时返回 `LIMIT`、阻塞或关闭连接。 |
| 算法参数 | 重传、ACK、拥塞控制和探测的调度上限，不是业务数据大小限制。 |

除非本表另有说明，字节数使用十进制字段含义，文档中的 KiB/MiB 使用 1024 为单位。内部 `uint16_t` 包长和端口字段也会额外受到 C 类型上限约束。

## 1. 公共 API 与 Context

### 1.1 必填字段和枚举

| 项目 | 当前限制 |
|---|---|
| `event_base` | 必须由调用方提供；Context 只借用，不创建、不销毁。 |
| `peer_id` | 必须是 1～128 字节的字符串；`NULL`、空字符串或超过 128 字节均非法。 |
| `target_peer_id` | 主动连接和 0-RTT 连接都必须是 1～128 字节。 |
| 地址族 | 仅支持 IPv4 和 IPv6；IPv6 的 `scope_id` 参与地址区分。 |
| 加密模式 | 仅支持 `none`、AES-GCM-128、AES-GCM-256。 |
| 流调度 | 仅支持 Strict 和 DRR。 |
| 拥塞控制 | 仅支持 DEFAULT（当前默认 BBR）、BBR、CUBIC。 |
| 流类型 | 仅支持双向和单向；流 ID 的四种组合由“发起方向/单双向”编码决定。 |
| Stream priority | 取值 0～7，0 最高；默认值为 4。 |

示例：`peer_id` 为 129 字节不会被截断，而是创建 Context 失败；目标 peer 不存在或长度为 0 时，主动连接不会创建。

### 1.2 Context 默认值与有效范围

下表针对 `utp_context_options_t`。除特别注明外，字段没有额外的人为最小/最大值，但必须能表示为其声明的 C 类型，并满足协议校验。

| 配置 | 显式传 0 的含义 | `*_INIT` 默认值 | 额外限制 |
|---|---|---:|---|
| `clock_granularity_us` | 非法 | 1 us | 必须大于 0。 |
| `bbr_init_cwnd_mss` | 非法 | 10 | 必须大于 0，不能小于最终最小 cwnd。 |
| `bbr_min_cwnd_mss` | 非法 | 4 | 必须大于 0，不能大于初始 cwnd；最终按最大 cwnd 收敛。 |
| `bbr_probe_rtt_ms` | 非法 | 200 ms | 必须大于 0；实现会保证不低于 50 ms。 |
| `bbr_min_rtt_expiry_ms` | 非法 | 10 s | 必须大于 0；实现会保证不低于 1 s。 |
| `bbr_pacing_gains` | 不适用 | 8 项 | 数组长度固定为 8，不能增加或减少。 |
| `cubic_beta` | 非法 | 0.7 | 必须满足 `0 < beta < 1`。 |
| `cubic_c` | 非法 | 0.4 | 必须满足 `0 < c <= 2`。 |
| `cubic_init_cwnd_mss` | 非法 | 10 | 必须大于 0；最终按最小 cwnd 和最大 cwnd 夹紧。 |
| `cubic_min_cwnd_mss` | 非法 | 4 | 必须大于 0，不能超过最大 cwnd。 |
| `zero_rtt_token_max_lifetime_seconds` | 有效期为 0，票据立即失效 | 600 s | 票据超过有效期不能用于 0-RTT。 |
| `zero_rtt_replay_cache_capacity` | 禁用抗重放缓存 | 4096 条 | Context 级抗重放缓存容量。 |
| `stream_terminal_capacity` | 非法 | 4096 条/连接 | 必须大于 0；终态流记录满后不能无限增加。 |
| `path_validation_buffer_capacity` | 禁用候选路径缓存 | 16 KiB | 只限制候选路径缓存，不限制 active path。 |
| `packet_in_max_free` | 不保留空闲缓存 | 256 个 | 只是空闲缓存水位，不是同时收包硬上限。 |
| `stream_send_buffer_capacity` | 非法 | 256 KiB/Stream | 必须大于 0；发送 ring 惰性创建，写入超过剩余容量时返回可恢复的满/阻塞结果。 |
| `stream_writable_space_rate` | 剩余空间达到配置比率时通知 | 500 | 范围 `(0, 1000]`；以发送 ring 剩余可写容量的千分比计算，`0` 非法。 |
| `handshake_timeout` | 非法 | 800 ms | 必须大于 0；被动握手首轮等待。 |
| `handshake_max_retries` | 不重试 | 2 次 | 这是额外重试次数，不是总发送次数。 |
| `pending_incoming_limit` | 不接受 pending | 1024 个 | Context 级未完成被动握手数量。 |
| `enable_keepalive` | 不适用 | true | 关闭后不发送空闲 Ping。 |
| `keepalive_interval` | 保活关闭时不调度；启用时非法 | 30 s | 启用保活时必须大于 0。 |
| `keepalive_timeout` | 启用保活时非法 | 1.5 s | 启用保活时必须大于 0，是单次 Ping 等待时间。 |
| `keepalive_probes` | 启用保活时非法 | 3 次 | 启用保活时必须大于 0；连续无响应后关闭连接。 |
| `max_idle_timeout` | 不通告空闲超时 | 30 s | 本端通告给对端的最大空闲时间。 |
| `ack_every_n_packets` | 非法 | 4 | 必须大于 0；实现会把对端 ACK-Frequency 请求限制在 1～64。 |
| `ack_delay_exponent` | 不表示默认 | 3 | 协议允许 0～20，超过 20 按 20 处理/拒绝编码。 |
| `ack_delay` | 非法 | 25 ms | 必须大于 0，最大 1000 ms。 |
| `initial_max_streams_bidi` | 不允许对端创建双向流 | 32 | 受 `uint16_t` 和对端流数量额度约束。 |
| `initial_max_streams_uni` | 不允许对端创建单向流 | 16 | 受 `uint16_t` 和对端流数量额度约束。 |
| `initial_max_data` | 不提供连接级额度 | 8 MiB | 协议最大值为 `2^60 - 1`。 |
| `initial_max_stream_data_bidi_local` | **非法** | 512 KiB | 必须大于 0；本端发起的双向流接收窗口。 |
| `initial_max_stream_data_bidi_remote` | **非法** | 512 KiB | 必须大于 0；对端发起的双向流接收窗口。 |
| `initial_max_stream_data_uni` | **非法** | 512 KiB | 必须大于 0；单向流接收窗口。 |

当前没有把三个初始 Stream 窗口强行限制在 64 KiB～4 MiB；它们受协议最大值和 `uint64_t` 表示范围约束。三个字段配置为 0 会在 Context 创建时失败，因为它们必须提供正的初始窗口。

Connection 内部直接初始化（不经过 Context 公共选项）还保留兼容默认值：双向流 64 条、单向流 32 条；正常 Context 创建会用上表中的 32/16 覆盖它们。

### 1.3 主动连接和 NTRS/NAT 参数

| 项目 | 默认/限制 |
|---|---|
| `utp_connect_options_t.timeout_ms` | 0 非法；`retries=0` 表示不重试。默认超时由 `UTP_CONNECT_OPTIONS_INIT` 提供，为 3000 ms。 |
| 0-RTT `early_data` | 只用于首条双向流；数据可能被重放，应用必须保证幂等或自行去重。 |
| NTRS 注册/地址更新 timeout | 0 非法；默认值由 `UTP_NTRS_REGISTER_OPTIONS_INIT` 提供，为 1000 ms。各自的 `retries=0` 表示不重试。 |
| NTRS keepalive | 默认间隔 15000 ms，等待 PONG 默认 3000 ms；连续三次无响应删除注册。 |
| NAT 探测阶段 timeout | 0 非法；默认值由 `UTP_NAT_PROBE_OPTIONS_INIT` 提供，为 3000 ms；实际最小值 6 ms。 |
| NAT 探测并发 | 最多 6 个在途请求，每轮最多发送 2 个，最多 2 轮。 |
| NAT 公网端口样本 | 去重后最多保留 6 个。 |

## 2. 协议和线格式限制

### 2.1 包、包号和帧

| 项目 | 限制 |
|---|---:|
| 协议版本 | 当前实现为 v3。 |
| 固定包头 | 20 字节。 |
| packet number | 0～`0x3fffffffffffffff`。 |
| 协议 MTU floor | 1280 字节；低于此值的路径不能作为正常 UTP 路径。 |
| PacketOut 每包最大帧数 | 8。 |
| PacketOut 每包最大 slice 数 | 8。 |
| UDP 单次 batch | 最多 16 个数据报。 |
| 单个 UDP 数据报的 iovec/WSABUF 数 | 最多 8 个 slice。 |
| ACK range | ACK 编码最多 256 个 range；接收端提供的 range 数组不足时返回 `LIMIT`。 |
| packet-out bucket | 最多 8 档；当前实现使用固定的五档容量。 |
| PacketOut 惰性扩容 | 每个 bucket/描述符池每次扩容 32 个对象。 |

固定帧长度（不含可变长度 payload）如下。帧是否能放入一个 UDP 包，还要扣除包头、加密 tag 和同包其它帧的长度。

| 帧 | 固定部分 |
|---|---:|
| PATH_CHALLENGE/PATH_RESPONSE | 9 字节 |
| VERSION | 5 字节 |
| HANDSHAKE_DONE | 9 字节 |
| STREAM header | 16 字节 |
| PADDING header | 3 字节 |
| CONNECTION_CLOSE header | 5 字节 |
| PING | 1 字节 |
| RESET_STREAM | 15 字节 |
| STOP_SENDING | 7 字节 |
| STREAMS_LIMIT | 4 字节 |
| CRYPTO | 35 字节 |
| SESSION_TOKEN header | 10 字节 |
| ACK_FREQUENCY | 7 字节 |
| TRANSPORT_PARAMS | 46 字节 |
| HANDSHAKE_DELAY | 5 字节 |
| MAX_DATA | 9 字节 |
| MAX_STREAM_DATA | 13 字节 |
| DATA_BLOCKED | 9 字节 |
| STREAM_DATA_BLOCKED | 13 字节 |
| RENDEZVOUS header | 4 字节 |
| OBSERVED_ADDRESS | IPv4 8 字节，IPv6 20 字节 |

Transport Parameters 的协议边界：ACK delay exponent 最大 20；连接级和 Stream 级 flow-control 值最大为 `2^60 - 1`；ACK-Frequency 的 ACK-eliciting threshold 最大 64、reordering threshold 最大 32、delay 最大 1000 ms。

### 2.2 流 ID、流控和发送缓存

Stream 流控是“额度”，不是应用写入接口的单次写入大小。发送端只会把数据发送到对端通告的额度；额度耗尽后排队并发送 `STREAM_DATA_BLOCKED`。

| 项目 | 当前限制 |
|---|---:|
| Stream 默认接收窗口 | 512 KiB/Stream。 |
| Connection 内部默认接收窗口 | 2 MiB（直接初始化 Connection 时为 Stream 默认窗口的 4 倍）；通过 Context 公共 API 创建时，`initial_max_data` 默认是 8 MiB。 |
| Stream 发送 ring 默认容量 | 256 KiB/Stream，可由 Context 配置。 |
| Stream 可写通知阈值 | 默认 ring 剩余可写空间达到 50%；可由 `stream_writable_space_rate` 配置。 |
| Stream 单帧数据长度 | 受包 MTU、帧头和 `uint16_t` 数据长度限制，单帧不保证等于流窗口。 |
| Stream ACK range | 最多 16 个/Stream。 |
| Stream write view | 一次最多返回 2 个零拷贝 view。 |
| 接收重组单片最大距离 | `UTP_STREAM_RECV_MAX_GAP` 为 2 MiB；过远的乱序片拒绝。 |
| Stream 重组内存 | 最多 4 MiB/Stream。 |
| Connection 重组内存 | 最多 16 MiB/Connection。 |

`bidi_local` 和 `bidi_remote` 不是“本端发送/对端发送”的简单别名，而是按流的发起方命名：

- `initial_max_stream_data_bidi_local`：本端发起的双向流，允许对端向该流发送多少字节。
- `initial_max_stream_data_bidi_remote`：对端发起的双向流，允许本端向该流发送多少字节。
- `initial_max_stream_data_uni`：对端发起的单向流，允许对端向本端发送多少字节。

例如 B 把 `bidi_local=16 KiB`、`bidi_remote=1 MiB` 通告给 A：A 发起的双向流上，B 允许 A 接收最多 16 KiB；B 发起的双向流上，A 允许 B 接收最多 1 MiB。每个方向仍可通过后续 `MAX_STREAM_DATA` 增加额度。

发送例子：若 B 只给 A 1 字节额度，A 可以把 1024 字节写入本地发送 ring（只要 ring 尚有空间），但线上最多先发 1 字节；剩余数据等待 `MAX_STREAM_DATA`，额度不足时生成 `STREAM_DATA_BLOCKED`。如果 A 收到的线上 STREAM 已超过 B 通告的 `MAX_STREAM_DATA`，这是协议流控错误，连接应关闭，而不是静默截断。

## 3. 重传、ACK、保活和定时器

这些值是当前算法的保护边界，不改变协议可传输的数据总量。

| 项目 | 默认/上限 |
|---|---:|
| Connection 接收 ACK range | 32 个。 |
| ACK 乱序阈值 | 1 个包；ACK-Frequency 请求最大 32。 |
| ACK 延迟默认值 | 25 ms；编码最大 1000 ms。 |
| ACK profile 应用间隔 | 1 s；发送间隔 2 s；升级保持 3 s；回退保持 6 s。 |
| ACK 丢失观察窗口 | 2 s；频繁丢失阈值 2 次。 |
| 初始 RTT | 333333 us。 |
| 默认 RTO | 500 ms；最小 200 ms。 |
| 最大重传退避 | 10 次。 |
| TLP | 最多 2 次。 |
| 单次重传延迟 | 不超过 60 s。 |
| pacer 粒度 | 1000 us；burst token 为 10。 |
| Keepalive | 30 s 间隔、1.5 s 等待、最多 3 次探测。 |
| PATH_CHALLENGE | 1.5 s 超时，最多重试 3 次。 |
| Close PTO | 默认 333 ms，范围 10 ms～60 s。 |
| 被动握手延迟 | 初始 150 ms，最大退避 60 s。 |
| 事件循环定时器 | 单次延迟最大约 `UINT32_MAX` 秒；更大的延迟不能直接注册。 |
| CID 随机分配 | 单次最多尝试 8 个随机 CID；耗尽后返回分配/状态错误，不无限重试。 |
| 发送尝试索引 | 跳表层数最多 8；索引扩容块初始为 32 个节点。 |
| 接收历史极值 | min/max 采样窗口固定保留 3 个样本。 |
| 候选路径新地址挑战 | 观察到新地址后至少延迟 100 ms 再发挑战。 |
| 流控窗口更新 | 按连接级窗口的 1/10 触发；两次更新至少间隔 20 ms，BLOCKED 通知至少间隔 50 ms。 |
| PacketOut 使用采样 | 每 1024 次池活动记录一次使用水位，用于空闲 bucket 回收；不改变单次申请的容量选择。 |

ACK range 超过 256 不是“截断线上数据”：编码输入会返回参数错误，解码时如果调用方提供的 range 存储不足会返回 `UTP_INTERNAL_ERROR_LIMIT`。Connection 内部通常只为 32 个范围保留空间，因此业务侧不应假设能保留任意多的稀疏包号历史。

## 4. 路径验证与 MTU

### 4.1 路径验证

未验证候选路径受抗放大额度限制：

```text
发送上限 = 3 * 已认证接收字节 + 3 * 1280
```

额度还要扣除已经实际发送和已经排队的字节。候选路径缓存默认 16 KiB，可配置为 0 禁用。PATH_CHALLENGE 最多重试 3 次；验证失败不应自动关闭仍可用的 active path。

### 4.2 DPLPMTUD

| 项目 | 默认/限制 |
|---|---:|
| 探测开关 | 默认开启。 |
| MTU 最小值 | 1280；IPv4/IPv6 都按协议 floor 归一化。 |
| MTU 最大值 | 默认 1500，存储上限 `UINT16_MAX`。 |
| 初始 base | 默认 1400，并夹紧到 `[mtu_min, mtu_max]`。 |
| 阶梯步长 | 默认 16 字节。 |
| 单次探测超时 | 默认 2000 ms。 |
| 探测重试 | 默认 1 次额外重试。 |
| 稳定期探测间隔 | 默认 300 s，最小归一化为 1 s。 |
| 黑洞判定 | 3 个大包丢失、3 s 窗口、5 s 冷却。 |

启用 DPLPMTUD 时上述数值型参数显式传 0 均非法；`mtu_probe_retries=0` 例外，表示不做额外重试。例：`mtu_base=1600, mtu_max=1500` 会把 base 夹到 1500；`mtu_min=1400` 在 IPv4/IPv6 都有效，但若配置低于 1280 会被归一化到 1280。带 `UTP_PO_MTU_PROBE` 的探测包遇到 `EMSGSIZE` 会被 MTU 状态机消化并收窄上界；普通业务包遇到 `EMSGSIZE` 则是连接级 I/O 错误，应报告应用并终止，不能无限重试。

## 5. NAT、候选地址和 Rendezvous

| 项目 | 限制 |
|---|---:|
| NAT probe token | 12 字节。 |
| NAT probe packet | 固定 128 字节。 |
| NAT 在途探测 | 最多 6 个。 |
| NAT 每轮发送 | 2 个；最多 2 轮。 |
| NAT 映射端口样本 | 最多 6 个去重样本。 |
| 本地候选地址 | 最多 4 个；绑定 `0.0.0.0`/`::` 时按可用接口和稳定地址择优枚举。 |
| 公网候选地址 | 每个 CandidatePlan 最多 4 个，地址和端口作为完整 endpoint 去重。 |
| 地址观测样本 | 最多 4 个。 |
| Rendezvous attempt_id | 16 字节。 |
| registration token | 8 字节。 |
| punch/calibration token | 8 字节。 |
| Context 合并候选 | 最多 `4 * 2 + 1 = 9` 个。 |
| forward cache | 16 项，生命周期 30 s。 |
| Rendezvous output queue | 32 项。 |
| NTRS packet buffer | 512 字节。 |
| Rendezvous/握手 packet buffer | 1280 字节；用于满足协议 MTU floor。 |
| Pending handshake output | 最多 9 个待发送响应项。 |
| NTRS calibration 重传副本 | 每份固定 40 字节（20 字节包头 + 4 字节 Rendezvous header + 8 字节 token + 8 字节校准字段）。 |
| 地址更新去抖 | 5 s。 |

一个网卡下多个 IPv6 全局地址并不意味着全部无条件上报：实现最多保留 4 个本地候选，并优先稳定、可用于出站的地址；IPv6 link-local 地址必须保留 scope 区分。IPv4 不同网卡的地址和端口是不同候选，不能仅按 IP 文本合并。

## 6. 内存、池和队列

| 资源 | 当前限制/策略 |
|---|---|
| PacketIn 池 | 动态池每次增长 64 个描述符，每个稳定块 8 个；默认最多保留 256 个空闲对象。 |
| Pending packet | 每个待处理项最多保留 16 个包；pending storage 为 32768 字节。 |
| 0-RTT replay cache | 默认 4096 项，Context 级。 |
| NAT result | 结果缓存有效期 300 s。 |
| Hash table | 初始桶数按 2 的幂扩容；表项数受各表初始化的 `max_entries` 限制。 |
| Range set | `max_ranges` 是硬上限，达到上限时插入失败。 |
| Ring/Buffer | 初始化时必须有正容量；Buffer 扩容不能超过 `max_capacity`。 |
| Stream terminal slots | 初始 8 个，默认最多 4096 个/连接。 |
| PacketOut 描述符 | Connection 级按 32 个一组惰性扩容。 |
| PacketOut raw buffer | Context 级按 1280、1500、4096、9000、65535 等 bucket 惰性扩容；每次 32 个；最多 8 档。 |
| PacketOut | 单对象最多 8 帧、8 slice；耗尽返回资源错误，不现场无限增长。 |
| Stream 接收重组 | 采用惰性连续描述符数组；不设固定分片数量上限，同时受 Stream/Connection 内存和最大 gap 限制。 |

这些是资源保护，不是“最大连接数”。当前没有一个固定的最大连接数配置；实际并发连接数由可用内存、Connection/Stream 对象分配、PacketOut/PacketIn 池和操作系统 socket 资源共同决定。

## 7. 拥塞控制

| 项目 | 限制 |
|---|---:|
| BBR/CUBIC MSS | 1460 字节。 |
| BBR/CUBIC 最大 cwnd | `2000 * 1460` 字节。 |
| BBR PROBE_BW 增益周期 | 固定 8 项。 |
| BBR PROBE_RTT | 最小 50 ms。 |
| BBR min_rtt 过期 | 最小 1000 ms。 |
| BBR startup high gain | `(1, 4]`。 |
| BBR cwnd gain | `[1, 4]`。 |
| BBR startup growth target | `(1, 2]`。 |
| CUBIC beta | `(0, 1)`，0 或超范围值非法。 |
| CUBIC c | `(0, 2]`，0 或超范围值非法。 |

拥塞窗口上限只限制未确认飞行数据，不限制应用可以写入 Stream 发送 ring 的总量；后者仍受发送缓存和流控额度限制。

## 8. 加密、票据、地址和日志

| 对象 | 固定长度/限制 |
|---|---:|
| X25519 key | 32 字节。 |
| AES-128/AES-256 key | 16/32 字节。 |
| AEAD nonce/tag | 12/16 字节。 |
| nonce prefix | 每个方向固定 4 字节，包含在 12 字节 AEAD nonce 中。 |
| SHA-256 | 32 字节。 |
| resumption key/PSK | 32 字节。 |
| 0-RTT early attempt nonce | 16 字节。 |
| 加密服务端信息 | 密文 93 字节，明文 65 字节。 |
| 0-RTT token payload | 109 字节（16 字节 early-attempt nonce + 93 字节加密服务端信息）。 |
| Session token payload | 125 字节（32 字节 PSK + 93 字节加密服务端信息）。 |
| 本地恢复状态 | 最大 `UTP_CRYPTO_LOCAL_RESUMPTION_STATE_MAX_SIZE`，长度字段为 1 字节。 |
| Token | 固定 64 字节（12 字节 nonce + 36 字节 metadata + 16 字节 tag）；密钥每 3600 s 轮换，保留上一代密钥。 |
| 地址文本 | 最多 46 字节（IPv6 文本，不含端口和 scope）。 |
| remote host 文本 | 最多 46 字节。 |
| 日志 tag/message | 最多 256/2048 字节；超出会被截断或拒绝追加。 |

0-RTT 票据不能当作“绝不会重放”的认证数据；业务早期数据必须幂等。路径验证 token 还绑定地址族、对端地址和连接 ID，不能跨路径复用。

## 9. 错误和边界行为速查

1. **应用参数错误**：例如空 `peer_id`、0 Stream 窗口、无效枚举，返回 `INVALID_ARGUMENT`，不创建半成品对象。
2. **资源达到上限**：例如 ACK range 存储不足、pending 握手达到上限、PacketOut bucket 无可用对象，返回 `LIMIT`/资源错误；不会无限重试分配。
3. **对端违反协议**：例如收到超过 `MAX_STREAM_DATA` 的 STREAM、非法 ACK range、超过包头/帧长度，按协议错误关闭连接。
4. **普通业务发送 `EMSGSIZE`**：这是当前路径无法承载协议最低 MTU 的 I/O 错误，向应用报告并终止连接。
5. **MTU 探测发送 `EMSGSIZE`**：只收窄探测范围、回收探测包，不向应用暴露为连接失败。
6. **写入超过流控额度**：本地可以暂存到发送 ring；线上只发额度内数据，剩余数据等待窗口更新，并可能收到/生成 BLOCKED 事件。
7. **回调和日志**：日志 sink 同步执行，回调视图只在回调期间有效；应用不得保存 `reason`、日志 message 或零拷贝 Stream/PacketIn view 的裸指针。

## 10. 与 TODO 的关系

本文描述的是当前代码已经生效的限制。接收重组不再有固定的 Stream/Connection 分片数量上限；当前生效的是 4 MiB/Stream、16 MiB/Connection 的重组内存预算，以及 2 MiB 的最大乱序 gap。

代码位置发生变化时，应优先更新对应模块文档和本表；协议硬限制、公共 API 限制和资源保护上限必须分别标注，避免把内部防护误认为协议要求。
