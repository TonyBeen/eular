# 内存池与对象生命周期

## 1. 所有权层次

| 对象 | 所有者 | 生命周期 |
|---|---|---|
| Context、UDP socket、Context 级缓冲池 | 应用创建的 Context | Context create 到 destroy |
| Connection 槽位、PacketOut 结构体池 | Context/Connection | 连接建立到连接终止回收 |
| Stream、发送 ring buffer、接收分片 | Connection | Stream 创建到终态并从 Connection 回收 |
| PacketIn 数据缓冲 | Context PacketIn pool | UDP 收包到所有分片引用释放 |
| PacketOut raw/encrypt 缓冲 | Context buffer pool | 当前发送对象释放后归还对应桶；acquire 初始时两者可指向同一桶内存 |
| NTRS 注册和 Rendezvous 状态 | Context | 注册/尝试开始到完成、超时或取消 |

下层对象不拥有上层对象；公开 API 返回的 Connection/Stream 指针都是借用指针。

## 2. PacketIn 池

`utp_packet_in_pool_t` 以稳定分配块批量创建 PacketIn 描述符和数据存储。空闲对象通过侵入式链表复用；动态池按 grow/block 配置扩容，并可在空闲水位过高时回收块。

PacketIn 初次借出时 `ref_count` 为 1。Stream 乱序分片引用它时递增，分片消费或回滚时递减；计数归零后才回到空闲链表。这样可以让接收视图跨越一次收包处理，但不会让应用无限期占用缓冲。

## 3. PacketOut 池

PacketOut 分为两级：

1. Connection 级结构体池，按组申请固定数量的 PacketOut 描述符；
2. Context 级 raw 缓冲池，按 1280、1500、4096、9000、65535 等固定桶惰性按组扩容。

申请时选择能容纳请求大小的最小桶；桶耗尽时按每组 32 个对象/缓冲惰性扩容，失败则返回资源错误，不改变已有发送队列。释放时依据对象记录的桶索引 O(1) 归还缓冲。

PacketOut 的 `encrypt_data` 不是每个对象长期独占的加密副本。普通加密发送会使用 Context 级串行 `encrypt_send_buffer` 完成最终 UDP 输出；Connection 另有内联的 `close_packet_data` 保存关闭帧。

## 4. Stream 缓冲与内存预算

- 发送 ring buffer 保存未确认业务数据，是重传的唯一可靠副本。
- 接收分片直接引用 PacketIn，按 Stream 和 Connection 分别统计分片数量与内存成本。
- 预算耗尽时拒绝新的乱序片段或返回可恢复错误，不在收包热路径无限分配。
- PacketOut 的外部 slice 只能借用仍然有效的内部缓冲，不能指向调用方临时内存。
- Context/Connection 槽位、Stream、pending max-stream-data、终态记录、send-control attempt 节点、0-RTT early data、0-RTT 响应包号数组、replay/completed-attempt 表项和 crypto provider 上下文也可能按需分配；它们分别由 Context、Connection 或对应的状态表释放。

## 5. 失败与清理

分配失败只拒绝当前新操作，不能破坏已存在的连接、队列和哈希索引。Context/Connection 销毁按反向所有权顺序释放：先停止事件和定时器，再清空发送/接收队列，最后销毁池和 socket。
