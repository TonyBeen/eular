# Stream 与流控实现细节

## 1. Stream 生命周期

`utp_connection_create_stream()` 创建由 Connection 持有的 Stream；应用只能取得借用指针，不能单独销毁。Stream ID 按角色和方向分配，超过对端额度时返回流数量限制错误。

## 2. 发送路径

- `utp_stream_write()` 将数据写入发送 ring buffer。
- `utp_stream_acquire_write_views()` / `utp_stream_commit_write_views()` 允许应用直接写入内部可用视图。
- 只有 ACK 确认对应 offset 后，发送缓存才释放。
- FIN、RESET_STREAM 和 STOP_SENDING 通过 Connection 控制帧队列发送。

## 3. 接收路径

Stream 使用固定上限的 offset 排序分片数组。重复和重叠范围被裁剪，分片可以直接引用 PacketIn 的数据缓冲。`utp_stream_acquire_read_view()` 返回连续可读视图，`utp_stream_commit_read_view()` 完成消费并释放 PacketIn 引用。

## 4. 流控

- 连接级 `MAX_DATA` 限制所有 Stream 的累计数据。
- 流级 `MAX_STREAM_DATA` 限制单个 Stream 的 offset。
- 发送前超过对端窗口时返回 `UTP_STATUS_WOULD_BLOCK`，并排队 DataBlocked/StreamDataBlocked。
- 应用消费数据后推进本端窗口，排队 MaxData/MaxStreamData。

握手中的 `TRANSPORT_PARAMS` 为每个数据方向授予初始流级接收额度。参数归属的是通告方的接收方向：

| 参数 | 通告方 B 的含义 | 对 A -> B 的初始额度 |
|---|---|---:|
| `initial_max_stream_data_bidi_local` | B 发起的双向流 | B 发起该流时 |
| `initial_max_stream_data_bidi_remote` | 对端发起的双向流 | A 发起该流时 |
| `initial_max_stream_data_uni` | 对端发起的单向流 | A 发起该流时 |

例如 B 通告：

```text
initial_max_stream_data_bidi_local  = 16 KiB
initial_max_stream_data_bidi_remote = 1 MiB
initial_max_stream_data_uni         = 512 KiB
```

此时 B 发起双向流后，A 向 B 最初可发送 16 KiB；A 发起双向流后，A 向 B 最初可发送 1 MiB；A 发起单向流后，A 向 B 最初可发送 512 KiB。B 的应用消费数据后，B 通过 `MAX_STREAM_DATA` 增加对应流的最大可接收 offset。单向流仅有发起方到接收方一个数据方向，故不需要 `bidi_local`/`bidi_remote` 两类参数。

上述流控额度是滑动接收窗口：接收数据按需由 PacketIn 持有，应用消费后本端推进 `MAX_STREAM_DATA`，使对端持续拥有同等窗口大小的可发送额度。

`UTP_STREAM_RECV_FRAGMENT_LIMIT` 是单个 Stream 同时保留的乱序接收分片描述符数量上限，当前为 1024。每个描述符引用一个 PacketIn 数据区；它限制的是乱序、小分片造成的元数据和 PacketIn 持有量，不是流的字节接收窗口。顺序传输时，默认 1 MiB 窗口在最小 MTU 下不会达到该限制。

## 5. 异步读写通知

`on_readable` 和 `on_writable` 均由 Context 的零延迟通知事件异步派发，设置回调的当前调用栈不会执行用户代码。回调为水平触发：回调返回后，若回调仍非空且 Stream 仍可读或满足可写阈值，Context 会在下一轮事件循环再次通知。将 callback 设为 `NULL` 会取消后续通知。

每种通知使用独立队列节点，同一 Stream 在一轮内最多进入各自队列一次。派发时 Context 先取出队列快照；回调中未消费数据或未写入数据而重新满足条件的 Stream 只进入下一轮队列，避免单次 timer 回调自旋并阻塞 UDP 收包和协议 timer。

可写条件由 `stream_writable_low_watermark_per_mille` 控制。若发送 ring 容量为 256 KiB：`0` 仅在已确认并释放全部缓存后通知，`500` 在已占用容量不超过 128 KiB 时通知，`999` 几乎有任何可用空间时即通知。该阈值不代表对端流控额度，也不保证单次写入一定成功。

`on_closed` 保持终态转换时的同步单次通知语义，不属于上述读写通知队列。

## 6. 调度

Stream 支持 Strict 和 DRR 调度，priority 范围为 0 至 7。连接级调度在 Context 层执行，不绕过拥塞窗口、Pacer、流控或路径抗放大门限。
