# 默认值与调参指南

> 更新时间：2026-09-15
> 本文以 `c/include/utp/option.h`、`c/include/utp/context.h` 中的初始化宏和实际归一化逻辑为准。

## 1. Context 默认值

| 选项 | 默认值 | 说明 |
|---|---:|---|
| `stream_scheduler_mode` | `UTP_STREAM_SCHEDULER_STRICT` | 连接内 Stream 调度模式；另有 `UTP_STREAM_SCHEDULER_DRR` |
| `cc_algorithm` | `UTP_CONGESTION_DEFAULT`（BBR） | 新连接的拥塞控制算法 |
| `clock_granularity_us` | 1 | pacer 调度粒度 |
| `bbr_init_cwnd_mss` / `bbr_min_cwnd_mss` | 16 / 4 | BBR 初始和最小拥塞窗口 |
| `bbr_startup_high_gain` / `bbr_cwnd_gain` | 2.885 / 2.0 | BBR 增益 |
| `bbr_startup_growth_target` / `bbr_startup_full_bw_rounds` | 1.25 / 3 | BBR STARTUP 退出条件 |
| `bbr_probe_rtt_ms` / `bbr_min_rtt_expiry_ms` | 200 / 10000 | ProbeRTT 和 min-RTT 有效期 |
| `cubic_beta` / `cubic_c` | 0.7 / 0.4 | CUBIC 参数 |
| `cubic_init_cwnd_mss` / `cubic_min_cwnd_mss` | 32 / 4 | CUBIC 初始和最小拥塞窗口 |
| `enable_dplpmtud` | true | 是否启用路径 MTU 探测 |
| `mtu_min` / `mtu_max` / `mtu_base` | 1280 / 1500 / 1400 | MTU 下限、探测上限和初始安全值 |
| `mtu_probe_interval` | 300 s | 两次 MTU 探测的最小间隔 |
| `mtu_probe_step` | 16 bytes | 二分收敛停止精度 |
| `mtu_probe_timeout` / `mtu_probe_retries` | 2000 ms / 1 | 单次探测超时和额外重试次数 |
| `mtu_blackhole_loss_threshold` | 3 | 连续大包丢失阈值 |
| `mtu_blackhole_loss_window_ms` / `mtu_blackhole_cooldown_ms` | 3000 / 5000 | 黑洞统计窗口和冷却时间 |
| `zero_rtt_token_max_lifetime_seconds` | 600 s | 会话票据最长有效期 |
| `zero_rtt_replay_cache_capacity` | 4096 | Context 级重放缓存容量 |
| `stream_terminal_capacity` | 4096 | 每连接流终态记录容量 |
| `path_validation_buffer_capacity` | 16 KiB | 候选路径缓存上限；为 0 时禁用缓存 |
| `packet_in_max_free` | 256 | PacketIn 动态池最大空闲对象数 |
| `handshake_timeout` / `handshake_max_retries` | 800 ms / 2 | 被动握手响应的首轮超时和重试次数 |
| `pending_incoming_limit` | 1024 | 全局 pending 被动握手上限 |
| `enable_keepalive` | true | 是否启用连接空闲 Ping |
| `keepalive_interval` | 0 | 自动使用 `max_idle_timeout` |
| `keepalive_timeout` / `keepalive_probes` | 1500 ms / 3 | Ping 等待时间和连续失败次数 |
| `max_idle_timeout` | 30000 ms | 本端通告的最大空闲时间 |
| `ack_every_n_packets` | 4 | ACK-eliciting 包计数阈值 |
| `ack_delay_exponent` / `ack_delay` | 3 / 25 ms | ACK 延迟编码指数和上限 |
| `initial_max_streams_bidi` / `initial_max_streams_uni` | 32 / 16 | 初始流数量窗口 |
| `initial_max_data` | 8 MiB | 连接级接收窗口 |
| `initial_max_stream_data_bidi_local` / `...remote` | 256 KiB / 256 KiB | 双向流初始窗口 |
| `peer_id` | 无默认值 | 必须设置为 1 至 128 字节的 Context 标识 |

`event_base` 没有默认值，创建 Context 前必须由调用方提供。上述 0 值行为只适用于头文件注释明确说明了“0 时采用默认值”的字段。

## 2. 主动连接参数

`utp_connect_options_t.timeout_ms` 为单次握手超时，0 时使用 3000 ms；`retries` 是主动连接的额外重试次数。它们与 Context 的 `handshake_timeout`/`handshake_max_retries` 不应混为一谈。`address`、`port` 和 `target_peer_id` 是必填项。

`utp_connect_0rtt_options_t` 还要求有效的会话票据；早数据可能被重放，只能承载幂等或应用自行去重的数据。

## 3. ACK、保活和 MTU 调参

- 交互业务优先降低 `ack_delay`，但应同时观察 ACK 数量和重传率。
- 长连接保活优先调整 `keepalive_interval`，再调整 `keepalive_timeout` 和 `keepalive_probes`。
- MTU 探测优先保持 `mtu_min <= mtu_base <= mtu_max`；`mtu_probe_step` 越小，收敛越精细但探测轮次越多。
- BBR/CUBIC 参数只影响新建连接；修改后应分别观察握手突发、RTT、丢包和吞吐。

## 4. NTRS 注册参数

`utp_ntrs_register_options_t` 的 `timeout_ms`、`address_update_timeout_ms` 默认均为 1000 ms，注册和地址更新默认各重试 3 次；`keepalive_interval_ms` 默认 15000 ms，`keepalive_timeout_ms` 默认 3000 ms。Context 销毁不会隐式反注册，应用需要显式调用 `utp_context_unregister_ntrs()`。

## 5. 验证指标

调参时至少记录建连成功率、握手耗时 P50/P95/P99、ACK/重传率、RTT/RTTVar、写阻塞率、吞吐、进程 RSS 和单连接内存峰值。一次只调整一组相关参数。
