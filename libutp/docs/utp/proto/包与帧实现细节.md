# 包与帧实现细节

## 1. 代码职责

- `utp/src/proto/proto.c`：固定包头和包类型。
- `utp/src/proto/frame.c`：帧类型、长度计算和帧游标。
- `utp/src/proto/packet_in.c`：入站包对象池、包头解析和帧遍历。
- `utp/src/proto/packet_out.c`：出站对象、缓冲桶、slice 和发送尝试。
- `utp/src/proto/ack.c`：ACK 范围编解码和合法性校验。

## 2. 固定头、包类型与帧边界

每个 UTP 数据报以 20 字节固定头开始，所有多字节整数均为网络字节序：

```text
scid:u32 | dcid:u32 | packet_number:u64 | payload_length:u16 | type:u8 | reserve:u8
```

- 当前线协议版本为 v3，由握手阶段的 `VERSION` 帧协商；固定头本身不编码版本。发送端当前将 `reserve` 写为 0，通用固定头解码器保留该字段供各上层包类型按需校验。
- `payload_length` 不含固定头，必须与 UDP 数据报剩余字节精确相等。帧游标必须恰好走到 payload 末尾，不能接受截断、溢出或尾随垃圾字节。
- 包号使用 62 位空间；普通连接发送尝试按单方向递增，重传一定分配新包号，迟到 ACK 通过发送尝试索引定位旧包号。无连接控制包使用独立的包号命名空间。
- 包类型分为 `INITIAL`、`HANDSHAKE`、`0RTT`、`CONNECTION_CLOSE`、已建立后的 `CTRL`、无连接的 `RENDEZVOUS` 和 `NAT_PROBE`。握手、连接和无连接控制包在 CID、允许帧集合及解复用路径上彼此隔离。

帧以 `type:u8` 开始。变长帧的长度字段只覆盖自身载荷；`ACK` 的所有 range 放在同一个 ACK 帧中。当前帧定义、定长字段与取值范围以 `utp/src/proto/frame.h` 为准；该文件中的格式注释是实现侧的线格式清单。

发送端按包类别先限制合法帧，再在可用 MTU 内组包：

```text
CONNECTION_CLOSE      单独成包
INITIAL / HANDSHAKE   仅携带握手阶段允许的帧
CTRL                  ACK、路径、流控、STREAM 等已建立连接帧
RENDEZVOUS/NAT_PROBE  仅携带各自无连接控制帧
```

`CONNECTION_CLOSE` 与其他帧共包不是接收端的格式错误；接收端先完成本包已验证帧的处理，再进入关闭状态。本端不会生成这种组合。

## 3. 入站处理

Context 从 PacketIn 池取得对象后，先校验 UDP 长度、固定头、版本和 payload 长度，再遍历完整帧区。解析不为单个帧分配内存，帧数据视图只在 PacketIn 存续期间有效。

处理分为三类：

- CID 为 0 的半连接报文、未知连接 CID 的普通报文和无法通过包头长度校验的 NAT/Rendezvous 报文，在进入连接状态机前静默丢弃。
- 已找到 Connection 后，未知帧、越界长度、非法 ACK 范围、违反流控或不允许的帧组合返回协议/流控错误；Context 会发送 `CONNECTION_CLOSE`，报告 `utp_on_connection_error_fn`，并让连接进入关闭收敛。
- 已配置 AEAD 的包认证/解密失败通常静默忽略，不改变连接状态；这是为了避免将随机 UDP 数据和错误密钥包变成连接关闭放大器。

## 4. 出站处理

PacketOut 同时保存：

- 当前包号、包类型和帧类型位图；
- raw 缓冲和外部 slice；
- STREAM offset、控制帧元数据和重传剥离信息；
- 目的 endpoint、MTU 探测标志和历史发送尝试。

PacketOut 结构体由 Connection 级池管理，raw/encrypt 缓冲由 Context 级大小桶池管理。重传使用新包号重新编码，不复用旧密文。

### PacketOut 生命周期与缓冲所有权

PacketOut 描述一个逻辑发送包，而不是一次 `sendmsg()` 调用。它保存当前包号、帧类型位图、帧语义元数据、raw slice、外部 STREAM slice、显式目的 endpoint 和历史发送尝试链。发送控制器在 scheduled、unacked 和 lost 队列之间转移对象；对象在任一时刻只属于其中一个队列。

- Connection 私有的 PacketOut 描述符按 32 个一组惰性增长，随 Connection 销毁释放。
- Context 共享的 raw buffer 按 `{1280, 1500, 4096, 9000, 65535}` 五档选择最小可容纳桶，同样每组 32 个惰性增长。空闲桶按采样峰值回收完整的空闲块。
- raw buffer 保存固定头、内联控制帧和 STREAM 帧头；STREAM 数据可作为 external slice 借用发送缓冲。借用区必须在对应 PacketOut 被 ACK、取消或销毁前保持有效。
- `UTP_PACKET_OUT_MAX_FRAMES` 和 `UTP_PACKET_OUT_MAX_SLICES` 都是 8；超出当前包容量时由组包器拆分为后续 PacketOut，而不是覆盖已有元数据。
- 释放时清除帧元数据、slice、尝试链引用和目的地址，再将描述符和 buffer 分别归还所属池。缓冲桶索引由对象保存，归还不做地址反查。

PacketOut 的密文不是重传源。加密包被重传或剥离瞬态前缀后，发送端重新写入包头、分配包号并执行 AEAD；旧密文随旧尝试退休。

## 5. 约束

- 固定包头和帧字段使用大端序。
- payload 长度必须覆盖实际帧区，帧长度之和必须恰好填满 payload。
- 包解析和 ACK 处理路径不允许隐式堆分配。
- PacketOut 不能保存应用传入的临时指针；外部 slice 的借用期限必须覆盖实际发送。
- 发送侧把 ACK、PING、PADDING 等瞬态帧置于 payload 前缀。丢失重传时只逻辑剥离该前缀，重写 payload 长度和 slice，不移动 STREAM 外部数据。
- 单个 PacketOut 至多编码一个 STREAM 帧；组包时先留出 ACK 和可靠控制帧空间，再以一个 STREAM 分片填充剩余 MTU。

## 6. 版本与传输参数

当前协议版本为 v3。`TRANSPORT_PARAMS` 为固定 46 字节帧，依次编码 `flags`、超时、初始流数量、ACK 延迟指数、连接级额度、双向流两类初始额度和单向流初始额度。

`initial_max_stream_data_uni` 是单向流接收方授予对端的初始发送额度。它与双向流额度一起进入握手协商和加密转录；因此新增该字段时协议版本从 v2 升至 v3，新旧实现不能互通。
